Name: Undecided

Platform: PC initially; other platforms possible later
Genre: FPS + RTS / tactical wargame
Multiplayer: Up to 8 players, server authoritative

The player commands military formations from an RTS perspective and can possess an individual unit to play in first person.

Core loop:

RTS command → Units execute orders → Possess unit → FPS combat

       └──────────── Return to RTS ───────────┘

5. Formations

BaseFormation derives from APawn.

A Formation represents an arbitrary collection of units.

Properties:

Can contain different unit types
Each BaseUnit belongs to only one Formation
Units are stored in an array inside BaseFormation
Formations are created by AdBellumGameMode
Units are spawned when their Formation is created
Units cannot currently be added/removed during gameplay
Formation splitting is planned

A Formation has:

FormationAIController
OrdersManagerComponent

The Formation has no physical world representation.

Order execution

An order can create a sub-order without replacing the main goal.

Example:

AttackUnitOrder
    └── ReloadOrder

or:

MoveLocationOrder
    └── TakeCoverOrder

After the sub-order completes, the main order continues.

The order queue automatically activates the next order when the current order finishes.

AI can create both orders and sub-orders.

9. Order Philosophy

Orders represent goals, while AI decides how to accomplish those goals.

For example:

Move to Location

does not necessarily mean:

Walk directly there regardless of danger.

The intended system supports two concepts:

Hard / Direct Order

The unit should prioritize the player's command and ignore environmental distractions.

Example:

Move to this location regardless of enemies.

Soft Order

The unit should pursue the goal while reacting to its surroundings and maximizing survivability.

Example:

Move to this location, but take cover or engage enemies if necessary.

The exact implementation of Hard vs Soft orders is not finalized.

bIsAggresive currently exists, but should not automatically be treated as the Hard/Soft system.

10. Formation → Unit Commands

Players command Formations.

Formation AI distributes the resulting goals/orders to BaseUnits.

Currently, a Formation's MoveToLocation command is ultimately sent directly to the units' OrdersManagerComponent.

The Formation itself does not navigate.

Formation-level tactical behavior is still under development.

AttackUnitOrder at the Formation level is not yet implemented.

17. Major Technical Problem

The biggest current problem is unit scalability.

Current units are full ALS Characters with individual:

Character/animation systems
AIController
AI logic
Perception
Navigation
Combat
Replication

This makes large numbers of units difficult to support with stable performance.

The developer is considering moving large-scale unit simulation toward Mass Entity, but no Mass implementation has started yet.

The target is to determine the practical maximum through testing rather than committing to a fixed unit count.

19. Important Rules for AI Assistants

When helping with this project:

Prefer C++ for core systems.
Do not unnecessarily move systems into Blueprint.
Maintain server authority and replication.
Do not invent class names.
Ask for code when implementation details are unknown.
Clearly distinguish implemented systems from planned systems.
Treat BaseFormation as a logical entity, not a physical group.
Treat BaseUnit as the physical battlefield entity.
Remember that each BaseUnit currently has its own AIController.
Remember that Formation AI and Unit AI are separate systems.
Orders represent goals; AI determines how to achieve them.
AI can create nested sub-orders.
Hard/Soft orders are planned concepts and are not fully implemented.
Do not assume bIsAggresive is equivalent to Hard/Soft.
Consider scalability whenever designing per-unit systems.
Mass Entity is only a future possibility, not an existing system.
State Tree migration is planned; current Behavior Tree architecture may change.
